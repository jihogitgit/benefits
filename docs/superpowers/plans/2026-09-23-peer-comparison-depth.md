## Task 1 — 금액 축을 열 수 있는 묶음이 있는가 (판정 먼저, 구현은 그다음)

이 작업은 **하지 않기로 끝날 수 있다.** 그게 실패가 아니라 이 태스크의 정상 결과 중 하나다.
먼저 판정하고, 통과한 묶음이 충분할 때만 구현한다.

### 이미 잰 것 (2026-09-23)

| 사실 | 값 |
|---|---|
| 금액 표기가 8할 이상인 묶음(5건 이상) | 37개 |
| `첫째`가 3건 이상인 묶음 | 7개 (출산장려금 37/45, 출산축하금 13/21 …) |

### 이미 드러난 반례 — 축은 묶음 안에서도 갈린다

`참전명예수당` 13건 한 묶음 안에서:
```
월 25만원 (70세 이상) / 월 20만원 (70세 미만)
월 17만원 / 월 22만원 / 월 25만원 (참전 종류별)
연 1회 80만원                      ← 단위가 다르다
```
`전입장려금` 9건 안에서:
```
1인당 20만원
율포해수녹차센터 입욕권 10매 + 종량제봉투 3매   ← 현물이라 수가 없다
1인 10만원 / 2인 20만원 / 3인 이상 30만원        ← 인원별이라 값이 하나가 아니다
```
`고령운전자운전면허자진반납`:
```
10만원, 단 실운전 증빙 시 20만원                 ← 조건부라 값이 하나가 아니다
```

한 행에서 수 하나를 뽑는 것 자체가 대부분 거짓이다. 그러므로 파서는 **뽑는 쪽이 아니라
버리는 쪽**으로 설계한다.

### 단계

- [ ] `scripts/probe-amount-axis.ts`를 만든다. 쓰지 않고 재기만 한다(읽기 전용).
- [ ] 한 행에서 값을 하나 뽑되, 아래 중 하나라도 걸리면 **뽑지 않고 버린다**:
  - [ ] 조건부: `또는`, `단 `, `증빙 시`, `경우`, `이상 시`
  - [ ] 인원·순위별로 값이 둘 이상 (`1인 … 2인 …`, `첫째 … 둘째 …`)
  - [ ] 현물: 수 옆에 `원`이 없는 수량 단위(`매`, `장`, `개`, `권`)
  - [ ] 단위가 섞임: 같은 행에 `월`과 `연`이 함께
- [ ] 버린 이유별 건수를 낸다. 이 표가 다음 판단의 근거다.
- [ ] 묶음마다 **통과한 행들의 단위가 하나인지** 본다. 둘 이상이면 그 묶음은 축이 없다.
- [ ] **판정 기준:** 통과 행 ≥ 5이고 단위가 하나인 묶음이 **10개 이상**이면 구현으로 간다.
      미만이면 Task 1을 여기서 닫고 `docs/seo-backlog.md`에 측정값과 함께 "안 한다"로 적는다.

### 판정을 통과했을 때만

- [ ] `src/lib/benefits/amount.ts` — 순수 함수. 입력은 `amount_text`, 출력은
      `{ value: number; unit: 'total' | 'monthly' | 'yearly' } | null`.
- [ ] 검사를 실제 원문으로 쓴다. 지어낸 문장은 쓰지 않는다 — 위 반례 넷은 전부 필수 케이스다.
- [ ] **손으로 대조한다.** 통과한 행 전부를 원문과 나란히 출력해 눈으로 읽는다.
      한 건이라도 틀리면 그 모양을 버리는 규칙에 추가하고 다시 잰다.
- [ ] 되돌려 증명한다 — 버리는 규칙을 하나씩 빼서 검사가 깨지는지 본다.
- [ ] 화면에는 축을 글자로 적는다("첫째아 기준 총액", "월 지급액"). 축을 안 적은 숫자 나열은
      독자가 제 마음대로 축을 상상한다.
- [ ] **통과 못한 행을 목록에서 빼지 않는다.** 빼면 목록이 완전해 보이는데 실제로는 아니다.
      "원문 확인"으로 남기고 링크는 그대로 둔다.
- [ ] 정렬은 축이 있는 묶음에서만. 없으면 지역 이름 순(지금과 같다).

## Task 2 — 표현 차이로 갈린 묶음 합치기

```
가정위탁아동양육보조금(24)  가정위탁양육보조금(10)  가정위탁아동양육비(7)
가정위탁양육(4)  가정위탁아동(4)  가정위탁보호아동양육보조금(3)
```

**부분 문자열 포함으로 합치면 안 된다.** `출산지원금`이 `장애인가정출산지원금`에 들어 있는데
둘은 대상이 다른 사업이다. 기계가 자동으로 정할 문제가 아니다.

### 단계

- [ ] 후보를 뽑는다 — 열쇠를 2글자 단위로 쪼개 겹침이 큰 쌍만. 자동 병합은 하지 않는다.
- [ ] 후보 쌍마다 양쪽 묶음의 실제 제목과 `target_text` 첫 줄을 나란히 출력한다.
- [ ] **사람이 읽고 정한다.** 판단 근거는 "대상이 같은가"지 "글자가 비슷한가"가 아니다.
- [ ] `data/peer-aliases.ts`에 `변형 열쇠 → 대표 열쇠` 표를 쓴다. 각 줄에 왜 합쳤는지 적는다.
- [ ] `peerKey`가 마지막에 별칭을 적용한다. 순수 함수를 유지한다.
- [ ] 합치기 전후의 묶음 수·건수를 기록한다. 줄어든 묶음 수만큼 사이트맵에서 URL이 사라지므로
      301이 필요한지 본다(사라지는 URL은 이미 색인됐을 수 있다).
- [ ] 되돌려 증명 — 별칭을 지우면 검사가 깨지는가.
