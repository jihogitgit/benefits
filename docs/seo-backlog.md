## 남은 것

### 1. GSC 데이터 대기 (막힘 — 사용자만 줄 수 있음)

Search Console의 검색어 CSV가 있어야 정할 수 있는 것이 둘이다.

- 새 주제 가이드의 우선순위 (건보료 / 귀농 / 한부모 중 무엇부터)
- 기존 10편의 `seo_title` 문구를 실제 검색어에 맞출지

지금 문구는 본문 논지에서 뽑은 것이라 검색어와 어긋나 있을 수 있다. 추측으로 고치면
되돌릴 근거가 없어지므로 데이터가 올 때까지 손대지 않는다.

### 2. 새 66장의 색인 추적

2026-09-23에 사이트맵에 올렸다. 색인은 요청과 무관하게 수 주 걸린다. 볼 것:

- 비교 페이지가 실제로 색인되는가 (얇은 목록으로 판정되면 안 된다)
- 상세 페이지의 "색인이 생성되지 않음"이 줄어드는가 — 이게 66장을 연 진짜 목적이다

줄지 않으면 원인이 인바운드 링크가 아니었다는 뜻이고, 비교 페이지는 되돌릴 수 있다
(`compareEntries`를 사이트맵에서 빼면 된다. 페이지 자체는 noindex로 남는다).

### 3. 금액 비교 (축 정의가 먼저)

지금 비교 페이지는 "어디가 또 하는가"만 답한다. "얼마인가"를 답하려면 `amount_text`를
파싱해야 하는데 두 가지가 막는다. 근거는 `src/components/benefits/PeerList.tsx` 주석.

- **축**: 970만원(총액) · 월 20만원×3회(월액) · 125만원씩 4년(분할)이 한 열에 섞여 있다.
  나란히 놓는 순간 서로 다른 것을 잰 값이 한 축에 서고, 그 순서가 곧 "여기가 더 많다"는
  주장이 된다.
- **발췌**: `amount_text`는 금액만 담긴 열이 아니다. "○ 지원대상 … ○ 지원금액 …"처럼 절이
  여럿이라 앞을 자르면 어떤 행은 금액이, 어떤 행은 대상이 실린다.

비교는 1,365장에 붙는 사실 주장이다. 파싱이 틀리면 수천 장이 거짓말을 한다.
